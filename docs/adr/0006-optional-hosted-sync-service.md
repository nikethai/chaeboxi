# Optional hosted sync service

Chaeboxi's initial SaaS offering is optional hosted storage and sync so users can share selected personal context across devices without operating a server. The user chose effortless sync over server-side indexing, retrieval, or learning; those advanced services are deferred rather than included in the initial subscription. Local use remains the foundation, while operating a hosted service is now an accepted business direction that revises the earlier preference to avoid hosting obligations entirely.

Encrypted sync is the recommended foundation, with processing remaining on devices for this initial service. User-held recovery for encrypted sync-only content is selected in [ADR 0009](0009-user-held-sync-recovery-key.md). Account setup, recovery mechanics, pricing, quotas, and device pairing still require design confirmation. No service deployment, billing setup, or implementation is authorized by this product decision.

The user confirmed first-version sync coverage for chats, canvases, memories, and learned procedures, with large KB documents opt-in. They subsequently proposed a higher tier that queries cloud-hosted knowledge without requiring the full KB on each device. The desired tier distinction is basic storage/sync versus optional hosted retrieval. This does not bring server-side autonomous learning into scope or require both tiers to launch together. Indexing, result delivery, costs, and limits remain unconfirmed; do not promise that an ordinary server can search an opaque encrypted backup.

The user approved hosted processing of collections explicitly enabled for cloud search. Other collections may remain encrypted sync-only or device-only. Cloud-search enrollment authorizes indexing and retrieval of the selected material, not silent promotion to authoritative knowledge or model training. Project scope, source references, and approval status must remain attached to retrieved results. The storage-only service and searchable service have different content-access boundaries that must be explained during setup. This approval is for product design, not uploading current user data.

Launch paid hosted sync first, then introduce the Cloud Knowledge tier after sync proves reliable. The user selected sequential delivery over launching both tiers together to keep operations manageable for one maintainer. Reliability gates, dates, and pricing remain to be defined.
