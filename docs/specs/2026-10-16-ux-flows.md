# Chaeboxi UX flows

Status: draft, 2026-10-16; maintainer reviewed the decisions list the same evening (dismiss guard, 3 retries, PM edit proposals explained). Companion to the [redesign brief](2026-10-16-redesign-brief.md); the brief holds the model, this holds the journeys. Wireframes: the "Chaeboxi redesign wireframes" canvas.

Conventions. **Trust** is the Auto/Ask setting from the brief. A **sheet** slides up inside the window and closes on Esc. **Review** is the home feed. Every step that changes something is undoable for 5 seconds (toast + ⌘Z) unless marked *final*.

## 1. First run

Trigger: first launch, or no model configured.

1. **Sign in to a model.** Subscription login (Google, ChatGPT/Codex) or "I have a key". One line under each: what that provider will receive.
2. **Connect a source.** Folder (native picker) · Gmail · Asana · Codex threads · Documents · Skip for now. Gmail and Asana open OAuth in the browser and return.
3. **Name the scope.** Suggested from the source (folder name, Gmail domain). "Is this a project or a client?" sets the vocabulary only.
4. **Trust.** One screen: "Chaeboxi acts on safe things first and shows you what it did. You can switch to asking first." Default Auto.
5. **First review runs** in the background. Review opens; a card says "Reading your folder… 2 min". Items appear as they are found.

Exits: Review with 1+ items, or Review empty with "Ask anything" pointing at Quick Chat. Skipped steps become "Needs you" items in Review, not blockers.

## 2. Ask (Quick Chat)

Trigger: global hotkey, menu bar icon.

1. Overlay opens with the last-used scope preselected (or none). Type, Enter.
2. Answer streams with source chips. If the answer used approved knowledge, a chip says so.
3. Exits: Esc closes (the exchange is kept as a chat in that scope, named by its first line) · "Continue in Chat" opens the main window on it · "Open scope" jumps to the scope page.

States: no model → the overlay shows "Sign in to a model" and nothing else. Offline provider → a plain sentence and Retry.

## 3. Review an item

Trigger: an item arrives (flows 7–11 produce them).

Item types: Proposal · Draft · Change · Done · Needs you · Conflict.

| Key | Action | Result |
| --- | --- | --- |
| A | Approve | Proposal → knowledge saved to the scope with its source link. Draft (Ask mode) → written into Gmail. |
| E | Edit | Inline edit, then A to approve the edited text. |
| X | Dismiss | Item leaves the feed (undoable). Second dismiss of the same fact in 30 days shows a small "Don't suggest this again" link under the toast; it is never the default action and needs its own click, so a double-tap of X cannot trigger it. |
| ⌘Z | Undo | Reverses the last action, 5 seconds. |
| ↵ | Open | Change → the source. Needs you → a chat with the question prefilled. Done → the result. |

Under Trust Auto, safe items arrive already applied, badge "Done", action Undo. Under Trust Ask they arrive waiting, action Approve. Items that always wait: anything that sends, deletes, edits files, or changes a decision.

Grouped by day; filter by scope; the Review count in the sidebar is the number of waiting items (not Done items).

## 4. Approve knowledge (detail of 3)

1. Approve → saved as *authoritative knowledge* in that scope (ADR 0001, 0002), source link kept.
2. If it contradicts existing knowledge in the same scope → not saved; a **Conflict** item is created instead (flow 12).
3. A *personal preference* ("answer in English") asks once: "Apply to all scopes?" Yes → global.

Final: approving is undoable for 5 seconds, after that it is edited or removed from the inspector's knowledge list, which keeps history.

## 5. Chat in a scope

1. New chat (⌘N) from a scope page starts in that scope; from Review it asks for a scope on the first send (chip in the composer, "None" allowed).
2. Each answer: one message, source chips below, inspector lists what was used.
3. The assistant may propose knowledge inline (a small card under the answer): Approve / Not now. Approved → flow 4.
4. Dragging a chat onto a scope in the sidebar moves it; its knowledge proposals move with it.

Composer: Attach · Scope · Improve writing · Tools · Send. Tools: Web search, Browser, Computer use, Swarm (per-conversation toggles).

## 6. Connect a source

Trigger: Settings → Sources → Add; "Add a source…" in the scope inspector; dropping a folder on a scope.

1. Pick the kind. Folder → native picker. Gmail/Asana → OAuth in the browser. Codex threads → detected store shown, "Connect" required (ADR 0003: detection yes, connection explicit).
2. Choose the scope (preselected when started from a scope).
3. **Background review** toggle, off by default, with one line: "Lets Chaeboxi read this source on a schedule to propose knowledge. Reading never makes anything authoritative."
4. First sync starts as Background work on the scope page; a Done item lands in Review when finished.

Exits: cancel at any step leaves nothing connected. Revoking a source keeps approved knowledge, marks its source links as "source removed".

## 7. The assistant wants to act (tool permission)

Trigger: in a chat, the assistant needs to edit a file, run a command, open a site that needs login, or use the computer.

1. A **sheet**: what it will do (one line), why (one line), what it touches (paths or site). Buttons: Allow once · Always in this scope · Not now.
2. "Always in this scope" is recorded as a per-scope permission, visible and revocable in the inspector.
3. Refusals are sentences in the chat ("I won't delete that folder because…"), never error dialogs.

Never automatic, whatever Trust says: send a message, delete, edit files outside a staged change, pay, change a decision.

## 8. Swarm run

1. Toggle Swarm in Tools, send as usual.
2. The thread shows one live card: "Working with 4 agents · round 1 of 2 · Stop". Agent turns do not appear in the thread.
3. Result: one answer by the captain, plus "Worked with N agents · rounds · tokens ›" collapsed below it. Expanding shows each role, provider and what it contributed.
4. Stop → the captain writes with what exists so far; the card says "Stopped early".

Cost: the inspector shows tokens and estimated spend for the run; Settings → Advanced → Usage keeps the history.

## 9. Background work

Started by: source sync (6), scheduled background review, Swarm (8), memory review.

- Appears in the scope page's Background work with a progress line and Stop.
- Finishing creates a Done item in Review with the outcome and a link.
- Failure: retry up to 3 times with backoff (10 s, 1 min, 5 min). Still failing → a Needs you item ("Gmail sync stopped: sign in again") with the fix as its primary action; no further retries until that action.
- Closing the window does not stop background work; quitting the app pauses it and resumes on launch.

## 10. Client email (PM)

Trigger: a new thread or reply arrives in a connected Gmail.

1. Route: is it a client? Which scope? (sender domain, Asana project). Unknown → Needs you: "Which client is this?"
2. Retrieve: matching threads, Asana tasks and comments, approved knowledge for that scope.
3. Judge: confidence tier.
4. Act:
   - High → label the thread, write a draft into it (Gmail draft, never sent). Review shows Done · Open in Gmail · Undo.
   - Medium → Review shows the draft as a Proposal: Approve writes it into Gmail; Edit first is the common path.
   - Low or conflicting facts → Needs you with the question and the candidates (flow 3).
5. Whatever the PM sends from Gmail is read back as a new source record. When the sent reply differs from the draft in a fact (a date, a number, a name), the difference becomes a knowledge proposal: "You told Acme 6 Nov; the draft said 4 Nov. Save 6 Nov as the launch date?" Tone or wording differences are ignored.

## 11. What changed (maintainer)

Trigger: opening Review, a scope page, or asking "what changed" in Quick Chat.

1. Items since the last time the scope was *viewed*: decisions and specs (from `docs/log.md`), commits grouped by author and branch, uncommitted work, branches created or deleted, board moves.
2. Each item links to its source (file, commit, card). Viewing the list marks it seen; nothing is dismissed automatically.
3. Asking in Quick Chat returns the same items as a paragraph with chips, and "Open scope".

## 12. Knowledge conflict

Trigger: a proposal contradicts approved knowledge in the same scope.

Review item "Conflict" shows both statements with their sources and dates. Actions: Keep the new one · Keep the old one · Keep both (asks for the condition that separates them) · Dismiss. Nothing changes until the user picks (ADR 0001).

## 13. Change Trust

From Settings → Memory and privacy, or the Review toolbar. A sheet explains both positions in two lines each. Applies to items that arrive from now on; existing items keep their state.

## 14. Search (⌘K)

One field. Results in three groups: Chats · Knowledge · Sources (files, threads, tasks). Enter opens; ⌘Enter opens in a new chat with the result attached. Scope filter chips above the results.

## 15. Errors and offline

- Provider error → in the chat, a plain sentence and Retry; the composer stays usable.
- Source auth expired → Needs you item in Review with "Reconnect".
- No network → Quick Chat and Chat work with a local provider if configured, otherwise say so in one line; Review and scope pages always work from local data.

## 16. Undo

Every approve, dismiss, draft write, label, connect and stop shows a 5-second toast with Undo and accepts ⌘Z. After that, the inspector's knowledge list and Background work history are the way back. Sent email and deleted files are never undoable from Chaeboxi, which is why they always ask first.

## Open questions

- Quick Chat inferring the scope from the frontmost app or folder: agreed as a later improvement, not v1.
- "Don't suggest this again" gets a visible list under Memory and privacy so it can be reversed.
- Background review default: off per ADR 0003's caution; the first-run flow may nudge it on for the first source.
