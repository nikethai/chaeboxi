# Dango UX flows

Status: accepted by the maintainer, 2026-10-17. Drafted 2026-10-16; maintainer reviewed the decisions list the same evening (dismiss guard, 3 retries, PM edit proposals explained). Companion to the [redesign brief](2026-10-16-redesign-brief.md); the brief holds the model, this holds the journeys. Wireframes: the "Dango redesign wireframes" canvas. Synced with the slice plans on 2026-10-17: see [Settled while planning](#settled-while-planning-2026-10-17).

Conventions. **Trust** is the Auto/Ask first setting from the brief. A **sheet** slides up inside the window and closes on Esc. **Review** is the home feed. Every step that changes something is undoable for 5 seconds (toast + ⌘Z) unless marked *final*.

## 1. First run

Trigger: first launch, or no model configured. A user who upgrades with a model already set up never sees it; one who later removes every model sees only step 1, then returns where they were. Quitting midway resumes at the same step.

1. **Sign in to a model.** Subscription login (Google, ChatGPT/Codex) or "I have a key". One line under each: what that provider will receive. No Skip: a model is required. A rejected key shows "Your {provider} key was rejected." with Update key.
2. **Connect a source.** Folder (native picker) · Gmail · Asana · Codex threads · Documents · Skip for now. Gmail and Asana open OAuth in the browser and return. Background review is on for this first source (off by default elsewhere, flow 6). Cancelling the picker or the browser sign-in leaves nothing connected.
3. **Name the scope.** Suggested from the source (folder name, Gmail domain); Gmail and Asana suggest Client. "Is this a project or a client?" sets the vocabulary and what the scope reads from Everywhere (flow 25). A name that already exists adds the source to that scope.
4. **Trust.** One screen: "Dango acts on safe things first and shows you what it did. You can switch to asking first." Default Auto. Knowledge always waits for approval, whatever is chosen.
5. **First review runs** in the background. Review opens; a card says "Reading your folder…" (or "Reading your Gmail…", "Reading your Asana tasks…", "Reading your Codex threads…", "Reading your documents…"), "Items appear here as they are found." and Stop; under it "Ask anything meanwhile: {hotkey}." Items appear as they are found.

Exits: Review with 1+ items, or Review empty with "Ask anything" pointing at Quick Chat. A skipped source step becomes a Needs you item in Review, not a blocker: "Connect a source so Dango has something to read.", action Connect a source (opens the add-source sheet).

## 2. Ask (Quick Chat)

Trigger: global hotkey (default ⌘⇧Space for new installs), menu bar icon.

1. Overlay opens with the last-used scope preselected (or none). Type, Enter. The chat is created on the first Enter and named by its first line; changing the scope after that starts a new chat.
2. Answer streams with source chips (up to four, then "+n"). If the answer used approved knowledge, a chip says "From approved knowledge".
3. Exits: Esc closes the window, not the answer (the exchange is kept as a chat in that scope and keeps streaming; reopening within 3 minutes shows it) · "Continue in Chat" opens the main window on it · "Open scope" jumps to the scope page (not yet planned, see below). The foot reads Esc · Rewrite ▾ · Continue in Chat.

States: no model → the overlay shows "Sign in to a model" and nothing else. Offline provider → "You're offline. {model} needs a connection to answer." and Retry; a local model still answers offline.

## 3. Review an item

Trigger: an item arrives (flows 7–11 produce them).

Item types: Proposal · Draft · Change · Done · Needs you · Conflict · Re-check (a draft or change built on knowledge that was since edited, removed or replaced).

| Key | Action | Result |
| --- | --- | --- |
| ↑↓ or J/K | Move | Between items. → enters an item's actions, ← returns. Keys never act while typing in a field or with ⌘, Ctrl or Alt held. |
| A | Approve | Proposal → knowledge saved to the scope with its source link. Draft (waiting) → Apply writes it into Gmail. |
| E | Edit | Inline edit, then ⌘↵ approves the edited text. On an item with no inline edit, E opens it (a draft opens "Edit the reply"). |
| X | Dismiss | Item leaves the feed (undoable, toast `Dismissed "…"`). Second dismiss of the same fact in 30 days shows a small "Don't suggest this again" link under the toast; it is never the default action and needs its own click, so a double-tap of X cannot trigger it. |
| ⌘Z | Undo | Reverses the last action, 5 seconds. |
| ↵ | Open | Change → the source. Needs you → a chat with the question prefilled. Done → the result. Conflict → focus on its first Keep this. |

Under Trust Auto, safe items arrive already applied, badge "Done", action Undo; Undo makes the item wait again, and an item that fails to apply waits instead. Under Trust Ask first they arrive waiting, action Approve. Trust Auto never approves knowledge: proposals and conflicts always wait (ADR 0001); Auto applies only safe actions that are not knowledge, such as a Gmail label or an unsent draft. Items that always wait: anything that sends, deletes, edits files, changes a decision, or saves knowledge.

Grouped Today / Yesterday / Earlier; toolbar: scope filter (All scopes, Everywhere, each scope), "Trust: Auto ▾", New chat ⌘N (starts in the filtered scope). The Review count in the sidebar is the number of open Needs you, Proposal and Conflict items (not Done, Change or Re-check), "99+" above 99. When an item leaves, focus moves to the next item, else the one above. Finished and dismissed items are kept 30 days.

## 4. Approve knowledge (detail of 3)

1. Approve → saved as *authoritative knowledge* in that scope (ADR 0001, 0002), source link kept. Toast: `Approved "{text}" for {scope}`. With no model available to check for contradictions, it is saved without the check.
2. If it contradicts existing knowledge in the same scope → not saved; a **Conflict** item is created instead (flow 12) and the card or toast says `Waiting in Review: it contradicts "{old}"`. Disagreeing with an Everywhere item is not a conflict: the scope item is saved and wins in that scope.
3. A *personal preference* ("answer in English") is saved to Everywhere wherever it is approved, with no question (ADR 0013).

Final: approving is undoable for 5 seconds (only the latest knowledge action can be undone; a newer one ends its undo), after that it is edited or removed from the scope's Knowledge tab, which keeps history.

## 5. Chat in a scope

1. New chat (⌘N) from a scope page starts in that scope; from Review it starts in the scope the Review filter shows. The composer's scope chip reads "No scope" when there is none and lists None and every scope, never Everywhere (Everywhere holds no chats).
2. Each answer: one message, source chips below, inspector lists what was used.
3. Every third turn the assistant may propose knowledge inline (a small card under the answer): "Save to {scope}?", Approve / Not now. At most three per answer, then "{n} more in Review". Not now leaves it waiting in Review. A chat with no scope proposes to Everywhere. Approved → flow 4.
4. Dragging a chat onto a scope in the sidebar, or the chat menu's "Move to scope…", moves it (undo: "Moved to {scope}"); its knowledge proposals move with it. Dropping on Everywhere is refused.

Composer: Attach · Scope · Tools ▾ · Model ▾ · Dictate · Send (see Composer under New rules). Tools: Web search, Browser, Computer use, Swarm (per-conversation toggles).

## 6. Connect a source

Trigger: Settings → Sources → Add a source; "Add a source…" on the scope page's Sources tab; dropping a folder on a scope page (this opens the native picker; the dropped path is never used).

1. Pick the kind: Folder · Gmail · Asana · Codex threads · Documents, then MCP server (leads to Advanced). Folder → native picker. Gmail/Asana → OAuth in the browser, or reuse an account already signed in. Codex threads → detected store shown ("Found {n} threads in {path}. Dango reads them only after you connect."), "Connect" required (ADR 0003: detection yes, connection explicit).
2. Choose the scope (preselected when started from a scope). A folder belongs to a project or client, never Everywhere, and a scope has at most one folder; a Documents collection belongs to one scope.
3. **Background review** toggle, off by default (on for the first-run source), with one line: "Lets Dango read this source on a schedule to propose knowledge. Reading never makes anything authoritative." It runs every 6 hours. Documents do not offer it.
4. First sync starts as Background work on the scope page; a Done item lands in Review when finished. Toast: "Connected {label} to {scope}".

Exits: cancel at any step leaves nothing connected. Removing a source ("Removed {label}. Approved knowledge stays.", 5 s undo) keeps approved knowledge, marks its source links as "source removed", unbinds a folder, and never deletes the Gmail or Asana account or the Documents collection.

## 7. The assistant wants to act (tool permission)

Trigger: in a chat, the assistant needs to edit a file, run a command, open a site that needs login, or use the computer.

1. A **sheet**: titled with what it will do ("Edit docs/a.md"), why (one line), what it touches (up to five paths or sites, then "and {n} more"). Buttons: Not now · Always in this scope (Always in this chat when the chat has no scope) · Allow once (first focus). Esc is Not now. One sheet at a time; one left unanswered for 2 minutes counts as Not now; Always also answers queued requests for the same tool.
2. "Always in this scope" is recorded as a per-scope permission, listed and revocable in the scope page's Settings tab under "Allowed without asking" (Stop allowing, with undo). A grant does not cover a riskier version of the same tool.
3. Refusals are sentences in the chat ("I won't delete that folder because…"), never error dialogs.

Never automatic, whatever Trust says: send a message, delete, edit files, pay, change a decision. These ask every time, never offer Always, and the sheet says "Dango always asks before it sends, deletes or changes your files."

## 8. Swarm run

1. Toggle Swarm in Tools ▾, mention 2 or 3 agents with @, send as usual. With Swarm off, a chat with several agents answers as the first one.
2. The thread shows one live card: "Working with 3 agents · planning", then "· round 1 of 3" (one round per task the captain planned), then "· writing the answer", with Stop. Agent turns do not appear in the thread.
3. Result: one answer by the captain, plus "Worked with N agents · R rounds · T tokens ›" collapsed below it. Expanding shows each agent, its provider and model, and what it contributed.
4. Stop → the captain writes with what exists so far, also when stopped while planning; the card says "Stopped early".

Cost: the cost heads-up (CS1) counts a Swarm run as two runs per agent. The inspector shows tokens and estimated spend for the run (not yet planned); Settings → Advanced → Usage keeps the history.

## 9. Background work

Started by: source sync (6) and scheduled background review (every 6 hours). Chat proposals (flow 5) replace the old memory review. Swarm (8) and plan runs show in their chat; listing them here is not yet planned.

- Appears in the scope page's Background work with a progress line and Stop ("Stopped {label}"; Undo starts it again), then the five most recent finished jobs.
- Finishing creates a Done item in Review with the outcome and a link (a background review only when it proposed something).
- Failure: retry up to 3 times with backoff (10 s, 1 min, 5 min); meanwhile the line says "Trying again shortly", never a count. Still failing → a Needs you item ("Gmail sync stopped: sign in again") with the fix as its primary action (Sign in again, Find the folder, Choose a model, Try again); no further retries until that action. Errors retrying cannot fix (expired sign-in, missing folder, no model) skip the retries.
- Closing the window does not stop background work; quitting the app pauses it and resumes on launch, a waiting retry at its planned time. "Pause background work" in the menu bar holds new runs; a run in progress finishes.

## 10. Client email (PM)

Trigger: a new thread or reply arrives in a connected Gmail (checked every minute; Asana every 2 minutes).

1. Route: is it a client? Which scope? (the addresses and domains of the scope's Gmail source). Unknown → Needs you: "Which client is this?", one per sender domain; newsletters, bulk and no-reply mail never ask. A new Gmail source starts with no addresses: answering adds the domain and reads its last 90 days. Only mail that arrives after the source was connected is acted on.
2. Retrieve: matching threads, Asana tasks and comments, approved knowledge for that scope.
3. Judge: confidence tier (High ≥ 0.85, Medium ≥ 0.6, else Low).
4. Act:
   - High → label the thread "Dango/Draft ready", write a draft into it (Gmail draft, never sent). Review shows Done "Reply drafted in Gmail: {answer}, per {sources}." · Open in Gmail · Undo. Under Trust Ask first, or after 20 drafts in a day, it waits like Medium.
   - Medium → Review shows the draft as a Proposal: Apply writes it into Gmail; Edit first ("Edit the reply") is the common path.
   - Low or conflicting facts → Needs you with the question and the candidates (flow 3). Answer opens a chat that lists the candidates; the answer the user picks or types is saved as approved knowledge for that scope (the user wrote it) and the reply is drafted.
   - Undo of a draft the PM has since edited in Gmail keeps it: "Couldn't undo. The change stays."
   - A source set to "Keep on this device only" is never sent to a cloud model; with no local model it asks "Choose a model".
5. Whatever the PM sends from Gmail is read back as a new source record. When the sent reply differs from the draft in a fact (a date, a number, a name), the difference becomes a knowledge proposal: "You told Acme 6 Nov; the draft said 4 Nov. Save 6 Nov as the launch date?" Tone or wording differences are ignored.

## 11. What changed (maintainer)

Trigger: opening Review, a scope page, or asking "what changed" in Quick Chat. No slice plan builds this flow yet (see Not yet decided).

1. Items since the last time the scope was *viewed*: decisions and specs (from `docs/log.md`), commits grouped by author and branch, uncommitted work, branches created or deleted, board moves.
2. Each item links to its source (file, commit, card). Viewing the list marks it seen; nothing is dismissed automatically.
3. Asking in Quick Chat returns the same items as a paragraph with chips, and "Open scope".

## 12. Knowledge conflict

Trigger: a proposal contradicts approved knowledge in the same scope.

Review item "Conflict" shows both statements with their sources and dates. Actions: Keep this on each statement · Keep both, with a condition… (sheet "Keep both", field "Both are true when…") · Dismiss (drops the new statement; the saved one stays). Nothing changes until the user picks (ADR 0001).

## 13. Change Trust

From Settings → Memory and privacy, or the Review toolbar ("Trust: Auto ▾"). A sheet titled "Trust" explains both positions, Auto and Ask first, in two lines each, and lists what always asks. Applies to items that arrive from now on; existing items keep their state. Toast: "Trust set to {level}. Items already in Review keep their state."

## 14. Search (⌘K)

One field. Results in three groups: Chats · Knowledge · Sources (files, threads, tasks), at most 8 each. Enter opens (a knowledge hit opens the scope's Knowledge tab); ⌘Enter opens in a new chat with the result attached as a quote, in the hit's scope (no scope for an Everywhere hit). Scope filter chips above the results: All, then each scope. Esc closes and returns focus. Sources today are folder files and imported ChatGPT threads; Gmail, Asana and Codex results are not yet planned.

## 15. Errors and offline

- Provider error → in the chat, a plain sentence and the fix as its button ("Couldn't reach {host}." Retry; "{provider} returned an error." Retry), details behind "Show details"; the composer stays usable.
- Source auth expired → Needs you item in Review ("Gmail sync stopped: sign in again") with "Sign in again".
- No network → Quick Chat and Chat work with a local provider if configured, otherwise say so in one line ("You're offline. {model} needs a connection to answer."); Review and scope pages always work from local data.

## 16. Undo

Every approve, dismiss, draft write, label, connect, stop and remove, plus deleting, archiving or moving a chat, deleting a scope, changing Trust and Stop allowing, shows a 5-second toast with Undo and accepts ⌘Z (Ctrl+Z off macOS; never while typing in a field). One toast at a time: a new one replaces the old, and the old change stands. Only the latest knowledge action can be undone. An undo that fails says "Couldn't undo. The change stays." After that, the scope's Knowledge tab and Background work are the way back. Deleting a chat or a scope asks nothing first, because undo covers it. Sent email and deleted files are never undoable from Dango, which is why they always ask first.

## Open questions

- Quick Chat inferring the scope from the frontmost app or folder: agreed as a later improvement, not v1.
- "Don't suggest this again" gets a visible list under Memory and privacy so it can be reversed.
- Background review default: off per ADR 0003's caution; settled 2026-10-17: first run turns it on for the first source.

Decisions made while drawing, confirmed 2026-10-17: first run has five steps and Skip is offered on the source step only, never on the model step (a model is required); the conflict card offers "Keep both, with a condition…" as a secondary action; a failed background job shows the fix as its button and no retry count; Search opens as an overlay over the current screen, not a page.

Conflict outcomes (RV6, RV7). Keep this: the chosen fact is approved, the other is kept in history as superseded, and any draft or change built on the loser becomes a Re-check item in Review. Keep both: the user writes the condition ("Both are true when…"); both facts stay approved and the condition is stored on each.

Thinking and waiting (CH7, CH8). The answer area never goes silent. From the first token of thought, and even before it, the user sees one live line: the thinking mascot, a timer counting up, and the last line of thought as a rolling summary. The full thinking text is one click away: open by default in project scopes and in chats with no scope, closed in client scopes (it reads as noise to the PM); Settings › Advanced › Chat settings › Show thinking (Auto, Open, Closed) overrides it. Timed reassurance for slow models such as Qwen or Kimi: nothing extra before 8 s; "Still thinking" at 8 s; at 30 s one line, "Still working. Nothing is stuck; this model thinks before it writes." No model switch is offered mid-turn (it would mean cancelling, re-prompting, and explaining what happened); the timer, the moving summary and an always-visible Stop are enough. The composer stays live during the wait. Afterwards the line reads "Thought for {n} s ›" (a model that did not think leaves nothing), and tool calls fold into one line such as "Read 2 files · searched scope knowledge".

### Gaps closed on 2026-10-17

Features already in the code get a place in the new layout:

- **Copilots become Agents.** Saved personas (name, avatar, prompt, model settings, tool access, steps, hooks) live under Settings › Agents. There is no Copilots page. A scope can pick a default agent; Swarm picks up to three.
- **Plans are cards in the thread** (AG1, AG2). Run plan / Request changes / Reject (keys ↵ run · E change · Esc reject). A revised plan replaces the card and the old one folds to "Plan v1 ›". Progress shows inside the card ("Running plan · step 2 of 4"); a stopped plan reads "Plan stopped · 1 of 4 done" with Continue. When the plan finishes, its staged file edits arrive in Review as one Change item ("Plan finished: {title}"); a stopped plan, or one with nothing staged, files none.
- **Change Review is a Review item.** The folder scope's page gets a Files tab with the tree and branch status (FS1).
- **Scope page tabs**: Overview · Knowledge · Sources · Files (folder scopes only) · Chats · Settings. The inspector holds a chat's artifacts, not scope matters. The Settings tab holds the name, project or client, default agent, what the scope reads from Everywhere, "Allowed without asking", and Delete scope (a sheet; its chats move to Recents; 5 s undo).
- **Writing becomes Rewrite.** The Improve writing modal goes; Quick Chat has Rewrite (Clearer, Friendlier, Shorter, Formal, Translate) and chat has `/rewrite` (QC3), a sheet with Use this. Translate remembers its target language. Rewrite sends only the text and saves nothing.
- **Artifacts open in the inspector**, as in Claude: preview and code tabs, full screen, copy, download, versions (AR1).

New rules:

- **Composer** (CO1–CO3): attach · scope · Tools ▾ · model ▾ · dictate · Send, the same everywhere. Dictation is now a composer button (this reverses the earlier "voice stays in Settings" note). Typing `/` lists skills (up to five), then commands. Dropping files anywhere in the chat attaches them.
- **Model errors** (ER1–ER5) show the fix as the button: update the key, add credit, wait (rate limits follow the provider's Retry-After, else 10 s / 1 min / 5 min, then a Needs you item), answer without tools or choose a model that has them, start a new chat with a summary (named "{chat} (continued)"). Dango never switches models by itself, and checks a model's abilities before sending, never mid-turn; a model whose abilities are unknown is never blocked. Long chats get a quiet warning at 80% of the context: "This chat is {pct}% full. Early messages may be left out."
- **Cost** (CS1): a heads-up sheet ("This run may cost about {cost}", Run / Cancel) appears before a run whose estimate is over a limit set in Models and keys (default $0.50; 0 turns it off; off for local models). A run that has started is never interrupted.
- **Notifications** (MB1) only for Needs you items and runs of 60 s or more that finish while Dango is in the background; never for proposals, drafts, Done items or updates. Off until turned on. At most one every 10 minutes across all windows, the rest grouped ("2 things need you · 1 run finished"). Dango sets no interruption level, so macOS Focus and Do not disturb silence them as for any app. The menu bar shows the monochrome mascot in three states (idle, needs you, paused) and the rows Open Review ⌘1 · Quick Chat · Pause background work · Open Dango · Quit, under a status line such as "2 things need you · checked 5 min ago"; Windows and Linux keep the colour icon.
- **Window sizes** (RS1–RS3): three panes at 1200 px and wider, inspector docked at 380–460 px; from 760 to 1199 px the sidebar becomes a 56 px rail (Review, Search, Chats, Scopes, Settings) that opens over the content on hover or ⌘\, and the inspector a sheet from the right; below 760 px one pane with bottom tabs Review / Chat / Scopes / Settings (Scopes is a phone-only page), the inspector a sheet from the bottom, targets at least 44 px, and the tab bar hidden while the keyboard is open.
- **Dark mode** (DK1, DK2) uses the dark accent variants (#4FB894, #7EA2F0); the mascot turns light with dark eyes.
- **Accessibility** (A11Y1): screen readers hear one polite line about every 5 s while the model works ("Thinking, 12 seconds, {last thought}", then "Writing the answer, 20 seconds"), then the finished answer once, or "Stopped before answering.", never token by token. With reduced motion nothing moves: the mascot holds its idle pose and shows its state as text, and sheets appear in place. The first focus in a sheet is its primary action, or its field in a typing sheet; Esc closes and returns focus, ⌘Z undoes.
- **Empty states:** a new scope with no knowledge (EM1: "Nothing known about {name} yet", Start a chat / Add a source), Review before any source is connected (EM2: "Connect a source to get started", Connect a source / Ask anything; different from RV5 "Nothing needs you" with "Last checked …"), and a first chat with three suggestions from the scope (EM3).

### Knowledge after approval (KN1–KN3)

- Each scope has a **Knowledge** tab: search, filters (All, Facts, Decisions, Superseded; removed items show under Superseded), and per item its sources, where it applies, history, and the chats that used it. Row actions: Edit, Move to…, Remove.
- **Edit** saves a new version; the old wording stays in history. **Remove** has a 5 s undo and then moves the item to Superseded; nothing is deleted. Editing or removing knowledge a draft relied on creates a Re-check item, as a conflict does.
- **Add knowledge** by hand (Fact, Decision or Preference): what you write is saved as approved, with you as its source.
- Editing your own knowledge saves a new version; older versions are kept.
- Knowledge can carry a review date. When it passes, the item stays in use and a "Due for review" item appears in Review.
- **Everywhere** ([ADR 0013](../adr/0013-everywhere-layer.md)): a built-in scope read by every scope, holding preferences, facts and documents for all of them, but no chats. It is listed first and cannot be renamed or deleted; no scope may be called "Everywhere". A scope's own knowledge wins inside that scope. Client scopes take Everywhere preferences and facts but not its documents unless turned on (EV2); preferences are always on; switching a scope between project and client resets these to the new kind's defaults. "Never send email" is built in and cannot be removed.
- Settings › Memory and privacy (KN3) keeps the **Don't suggest again** list (answers the open question above), Trust and export, and links to Everywhere.
- Every source belongs to one scope (Everywhere counts as one, except for folders). The old "Knowledge base" is now the **Documents** source kind: files Dango searches when answering, never treated as approved knowledge.
- Old saved memory moves once, through a sheet ("Choose where your saved notes go"): each note goes to Everywhere, an agent's prompt, or is left out; nothing is deleted, and Later asks again on the next launch.
